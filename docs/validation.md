## 2026-09-23: skill draft and offline demo

The skill-creator frontmatter/naming validator accepted
`skills/reproduce-bug`. This checks structure, not agent decisions or triggering.

The included `fixtures/assertion/bug.cjs` was packaged through the actual CLI,
verified, run twice in fresh directories and rendered as Markdown. Both runs
returned exit 1 with `TOTAL_IGNORES_QUANTITY`; the runner reported `reproduced`.
Environment: Node 24.13.0, Windows x64 10.0.26200. No dependencies, API calls or
external services were used by the fixture. No implementation code changed in
this slice, so the existing full suite was not rerun for these documentation and
fixture additions.

This is one synthetic example and a CLI smoke check. It is not a skill quality
comparison, portability result, root-cause diagnosis or external-user validation.
The planned 12-case evaluation and real Linux lifecycle tests remain required.

using `/reproduce-bug` and the same fixture. The CLI reported API error 401
(invalid API key), zero input/output tokens and no model usage. No reproduction
artifacts were generated by Claude. Therefore neither explicit invocation nor

## Evaluation corpus preparation

`evals/` now materializes twelve independent synthetic workspaces and defines
the comparison protocol. Direct fixture checks cover the six deterministic or
secret-containing examples (two executions each), missing service environment,
and allowed outcomes of the two intermittent examples. The real package runner
also checks missing-lock setup failure and unsupported Python rejection.

The first missing-lock integration attempt hit the Windows supervisor's
20-second startup bound, before npm ran. A standalone recheck passed in 13.4
seconds; a separate PowerShell startup plus small C# compilation probe took 3.0
seconds. The cause of the transient startup delay is not established. Keep this
as a runner reliability follow-up before release; it was not a target reproduction
and the fixture test correctly rejected it. No timeout was relaxed to pass it.

These are corpus/runner checks. The three-arm model evaluation remains unexecuted.

## Linux namespace execution

Local Ubuntu/WSL2 validation used Linux 6.18.33.2, util-linux 2.41.3 and Node
24.13.0. The Node archive's SHA-256 was checked against Node's published checksum
list. Six namespace tests passed both as root and UID 65534: detached-child
cleanup on normal exit, timeout/cancellation, owner SIGKILL, outer-supervisor
SIGKILL, refused namespace startup, and exact arguments/UID/exit 125 preservation.

The full Linux suite passed 69 tests with 7 platform-specific skips (90.4s).
The Windows runner/supervisor/report regression slice passed 26 tests (168.6s).
The original Linux baseline had 62 passes, 2 npm timeouts and 6 skips. An offline
probe with a longer explicit timeout measured 38.2s for missing-lock npm startup;
a valid locked package reproduced twice in 80.8s including both installations.
The npm test recipes now explicitly allow 60 seconds per phase. Production
defaults and the independent 20-second supervisor startup bound are unchanged.

Hosted CI is configured for Node 22/24 on Ubuntu 22.04 and Windows; its results
must be checked separately before claiming those combinations passed.
